Details

Production systems are won in the boring corners

  • Crash-safe click accounting - analytics increments live in Redis; every 30s a cron does batch UPDATE … click_count + :inc, and only after Postgres commits does it DECRBY the Redis counters. A worker crash mid-cycle loses nothing and double-counts nothing.
  • Textbook distributed locking - the flush lock is SET NX EX with a UUID token, released by a Lua compare-and-delete script that verifies the token first. No releasing someone else's lock.
  • Sonyflake IDs with a custom epoch (2014-09-01), Base62-encoded with a hand-rolled encoder - short, sortable, collision-free aliases without a central counter.
  • Cache TTLs that respect expiry - expiring links cache for min(3600, seconds_until_expiry) so a link never outlives itself in cache. Banned links cache a "BANNED" sentinel; unknown custom domains get negative-cached for 5 minutes.
  • Custom domains via Cloudflare for SaaS - programmatic hostname registration, HTTP DCV, TLS 1.3 + HTTP/2 forced on, plus a DNS-resolution fallback check against flexurl.app A-records via dns.google.
  • SSRF protection on user-submitted URLs - parse, reject literal private/loopback IPs, then getaddrinfo and reject if any resolved IP is private, loopback, link-local or multicast - then a HEAD liveness probe with a 2s timeout.
  • Async malware screening - every new link goes to Google Safe Browsing v5 (uris:batchGet) as a background task; a hit marks the URL banned in Postgres and overwrites the Redis entry with the "BANNED" sentinel.
  • Geo-priced monetization - Razorpay tiers priced by CF-IPCountry: ₹799/₹2499 in India, $11/$29 international, ₹9/$0.10 one-time 14-day trial, 7-day dunning grace with staged warning emails.
  • Exactly-once daily reports - claimed with Redis SET NX and an O_CREAT|O_EXCL file fallback, so the report fires once even if Redis is down.
  • Instrumentation everywhere - debug timers on Redis GETs, DB queries, enqueue durations, webhook dispatches. The 42ms average was found by measuring, then shaving.

The crash-safe flush, condensed

# 1. read counts → 2. commit to postgres → 3. then decrement redis
async with db.begin():
    await db.execute(
        text("UPDATE urldata SET click_count = click_count + :inc WHERE short_url = :u"),
        batch,  # up to 1000 rows per cycle
    )
# only after commit succeeds:
await redis.decrby(key, inc)   # crash before this ⇒ next cycle retries, nothing lost
