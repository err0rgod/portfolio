Design

Security primitives, not opinions about your schema

  • Argon2id by default - password hashing via argon2-cffi's PasswordHasher with the OWASP-recommended algorithm. No md5 nostalgia here.
  • Refresh tokens are NOT JWTs - they're secrets.token_urlsafe(64) opaque strings, and only their SHA-256 hash ever touches a database. A leaked refresh-token table leaks nothing usable.
  • JWT access tokens, 15-minute fuse - sub, jti, iat, exp - short-lived by default so a stolen access token expires before lunch.
  • Dict-style API - Security["hash"](pw), Security["verify"](pw, hash), Security["reset"](...). An unusual, javascript-flavored interface that makes the security surface feel like a toolbox, not a framework.
  • @require_auth decorator - wraps any function whose first arg is a token string; the decoded payload is injected into your handler. Framework-agnostic: Flask, FastAPI, raw sockets, whatever.
  • Duck-typed rate limiting - RateLimiter(storage_client) works against anything exposing .incr() and .expire(). Redis, memcached, a dict in a trench coat - all valid.
  • Brute-force hooks - verifyPassword accepts locked_until / failed_attempts and refuses to even try while locked. State stays with you; the primitive enforces it.
